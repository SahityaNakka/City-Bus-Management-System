# Acceptance Test Checklist — Project 22 (CityTransit DEMO)

## Verified Capabilities
- [x] **Authentication & 7-Role RBAC**: JWT login/signup (`POST /api/auth/login`, `POST /api/auth/register`), server-side `require_roles` authorization (`401`/`403`), role-filtered `Sidebar` & `RoleGuard` in React.
- [x] **Master Data & Route Validation**: Bus, Driver, Route, Stop, Schedule, Fare Rule, and User management connected to SQL via FastAPI; duplicate route-stop sequence rejection (`409`), inactive stop rejection (`400`), >=2 distinct active stops check before schedule publish (`400`).
- [x] **Trip Generation & Dispatch Conflict Control**: Idempotent trip generation (`POST /api/schedules/{id}/generate-trips`); assignment of eligible buses & drivers (`PATCH /api/trips/{id}/assignment`), rejecting `Maintenance`/`Inactive`/`On Leave` resources (`400`) and overlapping date/time assignments (`409`).
- [x] **Transaction-Safe Booking & Cancellation Cutoff**: Public/passenger trip search (`GET /api/public/trips/search`), row-locked seat capacity enforcement (`409 CAPACITY_EXCEEDED`), `Idempotency-Key` deduplication, `30`-minute cancellation cutoff enforcement (`400 CANCELLATION_CUTOFF_PASSED`), and Clerk `Completed`/`No-show` attendance controls.
- [x] **Driver Updates & Reports**: Driver sees only assigned trips + ordered route stops, records departure/arrival/delay category/passenger count (`0 <= count <= capacity`); Dashboard KPIs, all 6 filterable reports (`Trip Operations`, `Route Schedule`, `Booking Summary`, `Bus Utilization`, `Driver Assignment`, `Cancellations`), and `Audit Logs` with `FilterBar`, CSV export & print.
- [x] **Reusable UI & Production Readiness**: Reusable `Sidebar`, `Header`, `DataTable`, `FilterBar`, `FormField`, `StatusBadge`, `ConfirmDialog`, `Pagination`, loading/error/empty states; bell notifications (`GET`/`PUT /api/notifications`), standalone `migrate_db.py`, and 4-stage `tests/test_production_readiness.py` verification suite.
